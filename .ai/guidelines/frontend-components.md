# Frontend components & reuse

- Reuse order: project component (`resources/js/components/**`) → PrimeVue component → bespoke element last. Check for an existing component before writing one.
- Extract repeated UI structure into a component; don't re-wire inline. Form fields use one wrapper `components/FormField.vue` (label + required + error/hint; wraps the control in PrimeVue `FloatLabel variant="in"`, auto-injects `inputId`/`id` + `invalid` into the slotted control via `cloneVNode` — callers pass neither). Drop the PrimeVue control into its slot; no wrapper per control type.
- Local components are NOT auto-imported — import explicitly (`@/components/FormField.vue`). PrimeVue components are auto-imported (never `import` them).
- FloatLabel fields use the label as placeholder — don't also pass a `placeholder`.
- Icons are Tabler (`@tabler/icons-vue`), never PrimeIcons (not installed). When a PrimeVue control defaults to a PrimeIcon (e.g. Password's mask toggle), pass a Tabler icon via its icon slot (`#maskicon`/`#unmaskicon` with `toggleCallback`), positioned yourself.
- Layouts: guest/auth pages → `layouts/AuthLayout.vue`; authenticated B2B pages → `layouts/AppLayout.vue` (sidebar+topbar shell) via `defineOptions({ layout: AppLayout })`. Admin panel is separate. Sidebar `navItems` lists only existing routes — append a feature's nav entry when its page ships, never pre-add unbuilt links.
- User feedback uses flash **toasts**, never ad-hoc inline banners. Server side: `App\Modules\Core\Support\Toast::success|info|warning|error(...)`; `HandleInertiaRequests` shares as `flash.toasts`; `<AppToaster/>` renders them and must be mounted in every shell/layout. A failed validation request shows ONE generic error toast (`common.form_error`), never one per field — inline `FormField` errors are the per-field signal.
- **Destructive/mutating actions must confirm first.** Anything that deletes, removes, clears, or makes an irreversible server-side change MUST go through PrimeVue **ConfirmDialog** via `useConfirm()` before running — never fire on the raw click. Wrap the handler: `confirm.require({ header, message, acceptProps, rejectProps, accept: () => doIt() })`, labels/messages from lang keys (`common.confirm_title`/`delete`/`cancel` + a feature message). Pure client-side edits not yet persisted don't need it (the gate is irreversible/server-side effects). Don't pass a PrimeIcon `icon:` (Tabler only — omit or use `#icon`).
- Auth forms carry `autocomplete` tokens so password managers map fields: email = `username`, new-password fields = `new-password`, login current password = `current-password` (without a `username` field browsers mis-detect the first password input).
- **Reference projects (e.g. tezkolay) are for ideas, not wholesale copying** — build the minimal thing THIS project needs.
